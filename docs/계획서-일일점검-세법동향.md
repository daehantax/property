## 4. 작업 B — 매일 점검 프로세스 (`daily-check` 워크플로)

### 4-1. 점검 항목 (3계층)

| 계층 | 점검 내용 | 도구 | 실행 시간/비용 |
|------|-----------|------|----------------|
| ① 엔진 | vitest 289개 — 세액 계산·판정 로직 회귀 | `npm test` | ~6초, 무료 |
| ② 화면 | 정적 빌드 성공 + **스모크 테스트(신규)**: 13개 페이지 로드 시 JS 에러 0건, 대표 계산기 4종(증여·양도·재산·종부) 입력→결과 금액 표시, 판정기 5종 판정 출력, 주택임대사업자 체크리스트 렌더 확인 | `npm run build:static` + Playwright | ~1분, 무료 |
| ③ 세법 가정 | 기존 `law-watch` — 엔진 가정 8종을 AI 웹검색으로 최신 세법과 대조 (감시 대상을 아래 4-4처럼 확대) | Claude API + 웹검색 | ~2분, **API 비용 발생** |

### 4-2. 실행 스케줄 (제안)

- **매일 06:00 KST**: ①+② (무료 계층) — `daily-check.yml` 신설
- **③ law-watch**: 현행 주 1회(월) → **주 3회(월·수·금)로 확대** 제안
  - 매일 돌리면 한 달 API 비용이 계속 쌓이는데, 세법·판례는 하루 단위로 바뀌는 일이 드물어 주 3회면 실질 공백이 1~2일입니다.
  - 매일 원하시면 `daily-check.yml`에 합치면 됩니다 (→ §7 결정사항 ①)

### 4-3. 실패 시 동작

1. 워크플로 빨간불 → GitHub 기본 이메일 알림
2. **GitHub 이슈 자동 생성** (제안): 제목 `[daily-check 실패] 2026-09-05 — 스모크: 종부세 계산기 결과 미표시`, 본문에 실패 로그·의심 원인. 같은 원인 연속 실패 시 기존 이슈에 코멘트(이슈 중복 방지)
3. law-watch가 개정을 발견한 경우 → 이슈에 "고쳐야 할 상수 위치(constants.*)" 포함 + **작업 C 동향 일지의 '검토 중' 항목 후보로 등록**

### 4-4. law-watch 감시 대상 확대

현행 8종(상수 중심)에 다음 추가:
- 조정대상지역·규제지역 지정 변경 (중과 판정의 전제)
- 다주택 중과 유예·완화 관련 시행령 개정
- **대법원·조세심판원 주요 판결/결정** (1세대1주택 비과세, 중과, 이월과세 등 엔진 로직과 직결되는 쟁점) — 프롬프트에 "판결·심판 결정" 검색 지시 추가
- 국회 세법 의결 (12월) / 정부 세제개편안 발표 (7~8월)

### 4-5. 선행 정비

- 최근 2회 실패한 law-watch **리포트(artifact) 확인** → 2026 개정안 감지가 원인이면 동향 일지 초기 데이터로 활용하고, 가정값 갱신 여부 판단

**규모**: 중 (스모크 테스트 작성이 대부분, 1~2일)

## 5. 작업 C — 세법 동향 일지 페이지 (가칭 `law-updates.html` · 탭명 「세법 동향」)

### 5-1. 페이지 성격

계산기 알고리즘에 **영향을 주는 것만 선별**해 일자별(최신순)로 쌓는 타임라인. 단순 뉴스 모음이 아니라, 항목마다 "어느 계산기에 영향 / 엔진 반영 여부"를 붙이는 **변경 관리 대장**입니다.

### 5-2. 항목(1건)의 데이터 구조

별도 데이터 파일 `law-updates-data.js` 하나에 배열로 관리 — 항목 추가는 이 파일에 블록 하나 복사가 전부(초보자 기준 설계):

```js
{
  date: '2026-08-03',
  category: '정부발표',        // 법률 | 시행령 | 예규·해석 | 판결·심판 | 정부발표 | 규제지역
  title: '2026 세제개편안(정부안) 발표 — 부동산 세제 실거주 중심 개편',
  summary: '종부세 기본공제 실거주14억/비거주9억, 장특공제→장기거주소득공제(2028·2029 단계), 다주택 중과 한시완화(2027~28)…',
  affects: ['종부세', '양도세', '보유세허브'],   // 영향받는 계산기 태그
  engineStatus: '검토중',      // 반영완료 | 검토중 | 영향없음 | 국회심의중(미확정)
  engineNote: '미확정(국회 심의 중) — 확정 시 constants.AGGR_*, TRANSFER_* 수정 예정',
  sources: [{ label: '기획재정부 보도자료', url: 'https://...' }],
}
```

### 5-3. 화면 구성

1. 상단: 최근 점검 상태 배지 — "최근 자동 점검: 2026.9.5 ✅ 통과" (daily-check 결과 요약 파일을 읽어 표시)
2. 필터: 카테고리 / 영향 계산기 / 반영 상태
3. 일자별 타임라인 (최신순): 날짜 · 카테고리 배지 · 제목 · 요약 · 영향 계산기 태그 · 반영 상태 배지(**미반영='검토중'은 붉은 강조**) · 출처 링크
4. 하단: 운영 규칙 안내 (어떤 기준으로 선별하는지)

### 5-4. 초기 데이터 (백필 — 웹 조사로 확정 후 등록)

| 일자 | 항목 | 반영 상태(예상) |
|------|------|------|
| 2025.7.31 | 2025 세법개정안(정부안) 발표 | 영향없음(부동산 소폭) |
| 2025.10.15 | 규제지역 대폭 확대(서울 전역 등 조정대상지역 지정) | 반영완료 |
| 2025.12.2 | 2025 개정세법 국회 의결(거주주택 특례 정비·종부세 사후관리 등) | 반영완료 |
| 2026.5.10 | 다주택 양도세 중과 재적용(유예 종료) — 엔진 기준일 | 반영완료 |
| 2026.8.3 | 2026 세제개편안(정부안) 발표 — 舊 비교 페이지 내용 이관 | 국회심의중 |
| (조사) | 2025~2026 대법원·조세심판원 주요 판결 — 1세대1주택·중과·이월과세 관련 | 조사 후 판정 |

- 판결·심판 백필은 구현 단계에서 웹검색으로 조사해 "계산 로직에 실제 영향 있는 것"만 선별 등록합니다.

### 5-5. 운영 프로세스 (등록 흐름)

```
law-watch(월·수·금, AI 웹검색)  ──발견──▶  GitHub 이슈 자동 생성 (후보)
                                              │
                          사람(또는 Claude 세션)이 검토·확인
                                              │
                    law-updates-data.js 에 항목 추가  ──푸시──▶  페이지 자동 반영
                                              │
                (엔진 수정이 필요하면) constants 수정 + 테스트 → engineStatus '반영완료'로 변경
```

- 매년 반복 일정도 이 페이지가 흡수: 7~8월 정부안 발표, 12월 국회 의결, 이듬해 시행 — 舊 비교 페이지의 "연간 사이클" 역할 대체

**규모**: 중 (페이지+데이터 구조 1일, 백필 조사 반나절~1일)
